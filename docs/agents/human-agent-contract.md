# 人与 Agent 协作契约

> 本文是本项目的人类维护者、primary Agent 和 delegated Agent 之间的交互真源。它解决“谁来决定、什么时候继续、什么时候提问、怎样交接”的问题；产品术语和技术规则仍以 [`domain.md`](domain.md) 映射的项目文档为准。

## 0. 默认状态

维护者在任务中明确的目标就是本轮授权范围。对范围内的阅读、分析、文档修改、局部实现、测试和验证，Agent 可以直接推进，不为每个可逆的小选择重复请求确认。维护者说“交给你处理”时，按这个默认继续工作，并在真正需要决策时一次性列出选项。

外部写入、不可逆操作、产品行为取舍和最终集成仍然需要维护者决定。Agent 不能把“继续工作”解释成可以代替维护者做这些决定。

## 1. 三种角色与权限

| 角色 | 负责 | 不负责 |
| :--- | :--- | :--- |
| **维护者（Human）** | 产品目标、优先级、体验取舍、公开命名、不可逆操作、外部发布和最终集成 | 为 Agent 查找仓库内已有事实，或逐条批准已授权范围内的可逆动作 |
| **primary Agent** | 盘点现状、查证事实、统一术语、列出冲突、形成选项、编排工作、实施、验证、落盘和汇报 | 把猜测写成需求；绕过开工门替维护者拍产品决策 |
| **delegated Agent** | 在明确的票据或子任务范围内阅读、实现和验证，并返回证据 | 扩大范围、创建平行规则、覆盖别的 Agent 的结论，或自行解决未授权的产品冲突 |

同一项工作只有一个 primary Agent 维护任务全貌。delegated Agent 是有边界的执行者；primary Agent 必须审阅其结果、重新运行必要验证，并把结论合并到工作日志或票据中。

## 2. Agent 什么时候直接做，什么时候停下来问

### 可以直接推进

- 读取仓库、历史提交、测试、宿主文档和现有决策，查清可以由证据回答的事实；
- 在当前任务范围内整理工作日志、规格、票据、术语和其他已授权文档；
- 按已经确认的规格选择普通实现方式、补充必要的测试和运行验证；
- 修复明确且可复现的问题，或把发现的独立问题登记成票据；
- 运行检查、记录输出、整理差异，并报告剩余风险。

### 必须先停在决策点

- 用户目标、成功行为或核心术语有两种以上合理解释，且项目文档没有定论；
- 规格与 `AGENTS.md`、`DESIGN.md`、`HOST_ALIGNMENT.md`、术语表或已拍板决策冲突；
- 选择会改变产品行为、数据含义、公开命名、兼容承诺或长期架构方向；
- 操作会删除、覆盖、提交、推送、合并、发布、发送外部消息，或接触尚未提供的凭据；
- Ready-to-code gate 的关键证据缺失，继续编码只会把假设埋进实现；
- 环境或权限阻塞，且没有安全的本地替代工作。

遇到这些情况，Agent 先把已知事实和真正的分歧写清楚，再提出有限选项。只因为“还可以想出一个极端例子”不构成提问理由；先判断它是否改变验收、边界或实现。

## 3. 一轮工作的固定节奏

每项工作都按下面的循环推进：

1. **接收**：用一句话复述可验证目标，列出范围、未知事实和当前基线。
2. **对齐**：先读 `AGENTS.md`、本契约、`docs/dev/workflow.md`，再按 [`domain.md`](domain.md) 读取领域文档；核心术语不一致时先停在术语层。
3. **落盘**：把确认的术语、决策、规格、待决事项和阻塞写入唯一去向；不依赖聊天上下文保存结论。
4. **选择路径**：按工作流选择 Matt Skills 主流程或明确的一项 Superpowers 闸门，不叠加两套完整流程。
5. **执行**：满足 Ready-to-code gate 后才进入代码；否则继续查证、提问或整理票据。
6. **验证**：运行与改动匹配的检查，记录命令和结果；失败时保留复现证据，不用猜测掩盖失败。
7. **汇报**：说明实际改变、证据、未完成项、风险和下一步；必要的决定再次写回磁盘。

## 4. 提问协议：少问但问到主干

### 4.1 先问术语，再问需求

Agent 先查代码和项目文档。只有仓库证据无法消除歧义时才问维护者，并优先确认每个核心术语的定义、范围、拥有者、生命周期和容易混淆的相邻概念。术语统一后，才问业务目标、流程、规则、异常和边界。

### 4.2 每个问题都带选项和影响

每个需要人决定的问题使用这个形状：

```text
决策：需要决定什么
推荐：A。理由和依据是什么
选项：A / B / C（允许直接改写）
影响：每个选项会改变什么
阻塞：不回答会阻塞哪一个具体交付
```

事实问题由 Agent 自己查证，不把“我还没读文件”伪装成用户问题。问题应当能用 `A`、`B` 或一句补充回答；维护者也可以回复“按推荐”。

### 4.3 「30 + 20」检查点

- 一次只问当前 frontier 上的一小批问题，通常 3–10 个；前十个优先处理核心术语。
- 累积 30 个问题后，Agent 必须暂停拷问，检查核心业务、关键边界/异常和相互矛盾的描述是否已经清楚。
- 三项都清楚就输出需求确认文档并结束提问；仍有缺口时，每增加 20 个问题重复检查。
- 前置规则已经排除的边界不换一种说法重复问；frontier 为空时提前结束，不为凑数量制造问题。

检查点使用下面的句式，不能继续无目的扩散：

> 暂停拷问。请检查：核心业务目标、使用场景、流程、规则、异常和功能边界是否仍有未明确项；是否仍有关键边界或异常未确认；是否存在相互矛盾的描述。若没有，结束提问并输出需求确认文档。

## 5. 维护者的控制词

下面的短语是明确的运行控制信号，Agent 按字面执行并把状态落盘：

| 维护者说 | Agent 的动作 |
| :--- | :--- |
| `继续` / `按当前方案` | 继续当前任务，不重新打开已经解决的决定 |
| `采用 A` / `按推荐` | 记录选择和影响，继续被该选择解锁的工作 |
| `只读盘点` | 只读文件、运行安全检查并报告；不改文档、代码或配置 |
| `只改文档` / `不动代码` | 可以编辑文档、规格、票据和工作日志；不进入 `src/`、`tests/` 或构建配置 |
| `先落盘` | 先把当前确认内容写入唯一去向，再继续下一步 |
| `暂停` | 停止变更，保留现状并给出恢复点；可以等待新的指令 |
| `停止` | 结束当前任务，不再推进；先留下状态、证据和未决项 |
| `重做` / `返工` | 回到指定的最近决策或步骤，说明返工范围和原因 |

维护者在任务进行中发来的新消息默认是对当前任务的修正或转向。Agent 保留原目标中仍然有效的部分；只有维护者明确说“取消原任务”或提出互相排斥的新目标，才结束原工作。

## 6. 进度和阻塞汇报

长任务的 commentary 使用短格式，避免逐条转述命令：

```text
当前：正在处理什么，距离目标还差什么
证据：刚确认的事实、文件或验证结果
下一步：Agent 将继续执行的动作
需要你决定：只有真正阻塞的选择；没有就写“无”
```

长时间运行时，约每 60 秒给一次有信息量的更新。更新消息不夹带隐含问题；需要回答时单独列出决策、推荐项、影响和阻塞。没有新证据时不重复报同一状态。

阻塞报告至少包含：阻塞事实、已经尝试的查证、为什么不能安全猜测、可选路径、维护者回答后会解锁的工作，以及在等待期间仍能独立完成的工作。等待答案期间，Agent 继续做不依赖该答案的只读整理和文档落盘。

## 7. 上下文压缩与 Agent 交接

聊天记录不是持久存储。确认内容一出现就写入规格、票据、术语表、决策、工作日志或验证报告的唯一去向；上下文压缩、换模型、换会话或换 Agent 后，以磁盘内容为准。

新 Agent 的最小接手顺序是：

1. `git status --short --branch`、近期提交和 `docs/dev/worklog.md`；
2. `AGENTS.md`、本契约、`docs/dev/workflow.md` 和 [`domain.md`](domain.md)；
3. 当前主题的 `spec.md`、票据、`Blocked by` 和最近验证输出；
4. 只在需要时读取目标模块及其相邻测试。

交接或 delegated Agent 返回结果时，使用下面的最小包，不只说“做完了”：

```text
目标：
范围 / out-of-scope：
已确认术语和决策：
改动文件：
验证命令与结果：
剩余风险或未决项：
阻塞及 Blocked by：
下一步建议：
```

primary Agent 负责把交接包中的事实合并到工作日志和票据，并重新验证关键结论。任何新 Agent 都不能因为看不到上一段聊天就重新发明规则或重做已关闭的问题。

## 8. 结束条件

一项工作只有同时满足下面条件，才可以向维护者说“完成”：

- 用户可验证的目标已经实现，或明确记录为阻塞/暂缓；
- 改动范围、非目标、术语、决策和剩余风险已经落盘；
- 与改动匹配的验证命令有本轮输出；失败项和既有债务单独标出；
- 工作日志、票据和受影响的规则文档保持一致；
- 维护者知道下一步是什么，以及是否还有需要亲自决定或操作的事项。

如果任一项不满足，使用“当前状态 + 证据 + 缺口”汇报，不使用“应该可以”“大概完成”代替验证。

## 9. 维护者可直接使用的提示

```text
只读盘点当前工作区：按本契约汇报目标、基线、待决项和阻塞，不改文件。
```

```text
把已确认内容落盘，再继续；如果存在产品取舍，只给我带推荐项的有限选项。
```

```text
按当前规格执行到验证完成。遇到术语、规则或产品行为冲突先停下来，列出冲突双方和推荐选择。
```

```text
停止当前任务，保留工作区。请写交接包，包含改动、验证、未决项和下一步，不要继续修改。
```

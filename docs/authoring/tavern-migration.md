# 酒馆卡迁移清单

> 手上是 SillyTavern 卡（PNG 内嵌 / JSON）？本项目**不做运行时兼容**（D14 裁决），
> 走 **AI 单向转译**：一次性洗成原生卡包，之后各过各的。本页是转译时的验收清单。

## 为什么不搞兼容层

酒馆卡格式背着十年的历史包袱：宏引擎、正则世界书、隐藏通道指令。兼容它们意味着在我们的运行时里养一个 ST 模拟器——与「机制与内容分离、剧情理解归模型」的地基冲突。所以转译哲学是：**一次固化，运行时装干净静态文本，绝不做运行时正则扫描。**

## 转译映射速查

| 酒馆概念 | 转成 |
| :--- | :--- |
| `description` / `personality` | `card.md` 世界核心 + `skills/` 角色技能 |
| `first_mes` / `alternate_greetings` | `openings/*.md` |
| `scenario` | 世界核心或 persona |
| `mes_example` | 转写进 persona 的文风约定（示例对话体不适合直接搬） |
| `creator_notes` | `summary` / 注释 |
| 世界书条目（keyword 激活） | 语义知识 → `skills/`；**状态/数值触发** → `when:` 条件注入 |
| 状态脚本 / `setvar` | 世界状态字段（characters/flags/自定义字段）——无对应物的忍痛删 |

## 病根 A：模板宏（不清会直接坏）

<code v-pre>{{...}}</code> 宏宿主不认识。原则：**转译后不留活宏，全部固化为纯文本**。

- <code v-pre>{{random::a,b,c}}</code> / <code v-pre>{{pick::…}}</code> → 当场随机取一值写死；<code v-pre>{{roll::…}}</code> → 当场掷骰写死；<code v-pre>{{//注释}}</code> → 删；
- `setvar/getvar` 依赖酒馆运行时变量存储，物理不可迁移——检查语义能否转成世界状态字段，通常不能，删；
- **<code v-pre>{{user}}</code> 语义陷阱**：酒馆的 <code v-pre>{{user}}</code> 是玩家跨卡自设的「我」；我们的 <code v-pre>{{player.name}}</code> 是**卡声明的既定角色**（开局可覆写名字，见玩家手册）。若原文依赖「玩家自填」语义，转成中性第三人称，别留悬空指代；
- <code v-pre>{{char}}</code> → 卡角色名直接写死；
- **收口纪律**：映射完已知宏后，必须清除一切剩余 <code v-pre>{{...}}</code>（含双冒号、中文名、跨行等怪形态），只放行我们白名单里的 <code v-pre>{{player.name}}</code> / <code v-pre>{{player.description}}</code>。

## 病根 B：隐藏通道指令（不报错，但毁输出）

为「有原生隐藏思考通道」的模型写的指令，DeepSeek 系会**当正文原样吐出来**：

- 成对隐藏标签整段删：`<thinking>` `<thinking_rules>` `<output_lock>` `<comment>`、HTML 注释——**残留的半边标签再单独扫一遍**；
- 「打草稿：…」「每步思考字数限制」「内容输出规划」这类**话术按意图删**（要求模型先输出思考/草稿/规划的都算），别只背短语表——话术会过时，意图不会；
- 删了容器标签后，「总结 `<Prism>` 内的所有要求」这类**悬空引用要改写成自指完整句**（"总结所有写作要求"）；
- 无害容器标签可只剥标签留内容——判据是「宿主模型会不会把它当指令通道」，不是标签本身；
- 多轮删除后折叠连续空行（`\n{3,}`），免得污染排版虚耗 token。

## 转译验收清单（逐项打勾）

- [ ] 输出零残留 <code v-pre>{{...}}</code>（白名单两枚除外）；
- [ ] 零成对隐藏标签、零孤立半边标签、零 HTML 注释；
- [ ] 无「先输出思考/草稿/规划」类指令残留（按意图判定）；
- [ ] 悬空引用已改成自指句；
- [ ] <code v-pre>{{user}}</code> 语义已按玩家角色模型落定（卡声明 + 可覆写）；
- [ ] 连续空行已折叠；
- [ ] 世界书条目分流完毕：语义 → skills，状态触发 → `when:`；
- [ ] 全程一次固化，运行时零正则。

## 实操建议

转译是典型的「AI 干体力活、人做裁决」的活：把酒馆 JSON 喂给编码 agent，附上本页清单当验收标准，转完对着清单逐项检查。**卡越花，宏和隐藏指令越多**——社区大卡的转译产物务必人工过一遍病根 B。

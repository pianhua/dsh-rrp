# 技能与 when: 条件注入

> 卡包的知识层：模型按需调取的「上限」，与程序确定性注入的「下限」。

## 技能（Skill）基本形态

每个 `skills/<skill-id>/SKILL.md` 是一份标准 DSH Skill——frontmatter 的 `name` + `description` 决定模型**什么时候自己去查它**：

```markdown
---
name: 米娅 · 进阶人设
description: 关系升温后米娅的口吻变化、亲密小动作与患得患失。凡涉及两人独处升温时调取。
---

（正文：这个阶段她如何说话、动作、心理……）
```

description 的写法决定调取准确率：**写「什么时候该看我」，不要写「这是什么」**。反例「米娅的详细设定」；正例「凡涉及米娅的外貌、反应、口头禅或心理时调取」。

按需调取是**抬上限**——大部分设定模型自己会来找。但有些内容漏看一次戏就断（阶段性人设、规则开关），这就是 `when:` 的战场。

## when: 声明 = 保下限

在 skill frontmatter 加一行 `when:`，注入就不再指望模型自觉：

```yaml
---
name: 米娅 · 亲密阶段
description: 好感≥80 阶段人设。系统按世界状态自动注入，命中时无需再行调取。
when: trackedObjects.mia.character.affinity >= 80
---
```

引擎每轮对世界状态求值，命中即把片段以**裁决块**形态确定性写进执笔的上下文——模型无权跳过。块内自带三条纪律（全自动，无需你写）：

1. **穷尽声明**：「仅本块所列条目有效，此前所有条件注入一律作废」；
2. **撤销句**：命中集缩小时，掉出去的条目被点名作废——旧污染当场买断；
3. **调用纪律**：已注入的条目模型不再重复调取，省 token 也防口径打架。

## 条件语言（WorldState v2）

| 支持 | 写法示例 |
| :--- | :--- |
| 角色通用数值字段 | `trackedObjects.mia.character.affinity >= 80` |
| 对象级数值/布尔字段 | `trackedObjects.inn.fields.alert.value == true` |
| 全局数值/布尔字段 | `globalFields.identity_revealed.value == true` |
| 运算符 | `> >= < <= == !=` |

::: warning 明确不支持
- **字符串等值比较**——自由文本词表漂移会让保下限静默失效，拒绝是保护你。想让一句话可触发？把它建成布尔或数值字段；
- 嵌套逻辑（`&&` / `||` / 括号）——一条 when 一个原子比较，复杂条件拆成多个 skill；
- 未命中路径按不满足处理（不报错），所以字段名拼错 = 永不注入，用右侧栏状态面板核对字段名。
:::

## 预算与截断

单条片段 800 字符、总注入 2000 字符封顶，超出按 skill id 字典序截断。**when 片段写短**：只放「这个阶段的核心差异」，完整设定留在正文让模型调取。设定集页签顶部能看到此刻哪些 `when:` 生效、注入多少字符。

## 设计心法：机制与内容分离

引擎只写一次（求值、注入、撤销、缓存稳定），卡作者永远只写声明。对比旧酒馆：每个关键词激活都要在卡里塞正则——那是把机制外包给每张卡。你写 `when:` 时是在**陈述一个世界事实**，不是在配一条触发规则——这正是这套系统「程序管下限、模型管上限」哲学的落点。

# 架构决策记录（ADR）

记录**已经拍板的架构决策**：当时的背景、决定本身、以及**被否决的方案与接受的代价**。

ADR 一旦接受就保留，即使后来被修订或取代——被取代的记录仍能解释「为什么当初不是那么做的」。
**修改决策时新增一篇，不改写旧篇**；旧篇在状态栏标明被谁取代。

术语见根 [`CONTEXT.md`](../../CONTEXT.md)（领域词义与边界）与
[`docs/reference/GLOSSARY.md`](../reference/GLOSSARY.md)（命名对照与禁用旧词）。

## 关键脉络

单篇 ADR 只讲一个决定；**决定之间的推理链**才是真正难以重建的部分。以下六条是最重要的。

**状态权威的确定顺序（0004 → 0005 → 0006 → 0022）**
先确定「谁写状态」（0004：Chronicler 是有判断力的 Agent，不是提取器），再确定「谁能改状态」
（0006：玩家矫正是自然时序的最后写入，不是锁），最后才确定「状态里装什么」
（0005 动态结构 → 0022 划清 WorldState 管近期事实、剧情脉络管长线方向）。
顺序反了就会先造出一堆字段，再去争论谁该改它们。

**分支与地图（0009 → 0010 → 0024）**
0009 定了分支物理拓扑用原生 `Session.fork`；0010 把「画地图」这件事判给了外部插件 dsh-synapse；
0024 证明这个判断撑不住——世界线图确实是玩家高频需求，最终还是自己建。
0010 的教训已经写进它的「被否决方案」：**「暂不自建」不是「永不自建」**。
但 0010 的初衷（不把单一插件当唯一标杆）至今有效。

**呈现面要有归属（0021 → 0025）**
0021 在明确知道宿主提供官方聊天插入位的情况下，仍然选择聊天流内零插件内容——
「正文区属于宿主」。0025 把这个思路延伸成舞台：插件的表达力往自己的渲染面走，不往别人的呈现里掺。
这是本项目对「Host-First」理解最深的一条：**能不用宿主能力改造宿主呈现，就不用**。

**卡包格式的三步（0013 → 0014 → 0026）**
0013 决定「格式后定，不受旧格式约束」；0014 决定「不兼容酒馆，靠 AI 单向转译」；
0026 面对「转译工具算不算违反 0014」的张力，拍板为「卡包完全自有格式，酒馆仅为一次性导入转译的数据来源，
运行时零酒馆字段」。三步把「不兼容」从口号变成了可执行的边界。

**文风与破限（0016 → 0018 → 0020）**
0016 把句式级中文 AI 腔禁令升为常驻 persona（与「防全知」从 skill 升为铁律同一逻辑）；
0018 统一五个 Agent 的工程结构但严格分流业务内容——Author 的创作授权永不进数据管道；
0020 在此基础上叠加 JX 级逻辑护盾与全正向执行层。共同结论：**禁令要常驻，但不能外溢到别的场景**。

**文档编排（0027）**
2026-09-21 曾明确决定「不创建平行 CONTEXT.md / docs/adr/」。2026-10-16 所有者要求工程纪律对齐
dsh-tavern，该决定被取代，理由与代价写在 0027 里。**D1–D26 原编号全部保留不变**，
因此 `src/` 与 `tests/` 注释里既有的 `D6`、`D21` 引用零改动继续有效。

## 决策纪律

1. 每条决策都有所有者拍板依据，**AI 不得自行推翻**。
2. 实现中发现某决策不可行：**先回报所有者**说明具体阻塞，不默默改设计。
3. 变更决策时**新增一篇 ADR**并在旧篇状态栏标明取代关系，不改写旧篇正文；
   同时更新受影响的契约文档，并在提交信息中说明。
4. 实现细节（字段名、错误文案、UI 间距）不进 ADR，留给规格与票据。

## 复审机制

**机器能验的和只有人能判的，分开处理。**

可机械核验的（编号连续、状态栏存在、体积上限、相对链接有效）由 `pnpm run check:hygiene` 把关。

**判断性的只有人能做**：「D5 的动态状态结构今天还合适吗」「D16 的协议判断是否仍成立」——
机器永远查不出这类判断是否已经过时。因此每篇 ADR 头部登记 `> 最后复审`，复审周期 180 天：

- 复审时只回答一个问题——**这条决策的前提在今天还成立吗？**
- 仍成立 → 更新复审日期。
- 已失效或需改判 → **新增一篇 ADR 推翻它**，并在旧篇状态栏标注；旧篇不改写。
- 「周期到了但没空复审」不是阻塞项，`check:hygiene` 只警告不失败。

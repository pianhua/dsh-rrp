# 聊天流内不放插件内容（重申 2026-09-18 裁决，2026-09-20 再确认）

> 状态：接受（2026-09-20 知情后重申：宿主确有官方插入位，仍刻意不用）
> 原编号：D21 · 索引见 [README.md](./README.md)


**决策**：正文聊天流保持**纯宿主原生渲染**。插件界面一律落在自己的渲染面（`conversation.view` 舞台页签、右侧栏、主区面板），**不在每轮正文之间插入插件内容**。

**理由**：2026-09-20 做 #18（卡包自带界面）时勘察宿主，确认聊天流内其实**有官方可逆接缝**——`conversation.chat.turnTail`（每轮动作行前的 list 插入位）、`conversation.chat.assistant-actions`、以及 `ChatNodeDataMap` 声明合并 + `ctx.uiConversation.events.register` 的自定义节点链。也就是说「聊天内一行 HUD」在技术上完全做得到，**放弃它是产品选择，不是能力缺口**。所有者在知情前提下选择维持 9-18 裁决原样：正文区属于宿主，插件再放一行好看的东西进去，也仍然是往别人的呈现里掺东西，而舞台页签已经提供了更强的表达力。

**含义与边界**：
- 禁止项照旧：不注入对话区样式、不自定义正文排版、不 shadow `assistant-step`、不做沉浸视图（`story-view.tsx` 已删，不再恢复）；
- **禁止项之外也不做**：`turnTail` / `assistant-actions` / 自定义 chat 节点这些官方插入位，**未经修改本决策不得启用**；
- 卡包界面的表达力问题一律往「舞台页签」方向解决（声明式面板 / 沙箱卡页面，见 CARDS.md §13），不是往聊天流方向解决；
- 酒馆式「每条消息自带状态栏」的形态被明确排除在我们的设计之外——它属于移植酒馆体验，不属于 DSH 原生 RP。

**未来若真要重开**：先改本条决策，再谈实现；技术上一条 `slots.inject('conversation.chat.turnTail', …)` 即可，不存在需要先解决的难点。

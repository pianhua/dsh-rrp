# 文档真源：根 CONTEXT.md + 有序 ADR 取代单体 DECISIONS.md

> 状态：接受（2026-10-16 所有者拍板）
> 原编号：新增（原 D1–D26 体系之外）

**本 ADR 显式取代 2026-09-21「Agent 协作基线整理」中的一条编排约定**——当时的结论是
「继续以 `docs/reference/DECISIONS.md` 为唯一语义来源，**不创建平行 `CONTEXT.md` / `docs/adr/`**」。
原话见 [`docs/dev/worklog/2026-09.md`](../dev/worklog/2026-09.md) 的「2026-09-21 · Agent 协作基线整理」。

**决策**：领域词义与决策理由各自独立成真源，不再挤在一份文件里。

| 关注点 | 真源 | 形态 |
| :--- | :--- | :--- |
| 这个词**是什么、边界在哪** | 根 [`CONTEXT.md`](../../CONTEXT.md) | 领域词典，每个概念一节，边界用「**不是**什么」钉死 |
| **为什么**是这个设计、代价是什么 | [`docs/adr/`](./) | 一条决策一篇 ADR，带状态栏，被取代的保留不改写 |
| 中文 UI 名 ↔ 英文标识符、**禁用旧词** | [`docs/reference/GLOSSARY.md`](../reference/GLOSSARY.md) | 命名对照表 |
| 本月做了什么 | [`docs/dev/worklog.md`](../dev/worklog.md) | 流水账，按月切归档 |

**理由**：2026-09-21 那条约定的出发点是防止「同一件事有两份互相打架的真源」，这个出发点仍然成立。
但 26 条决策堆进一个 47.8KB 文件后，它同时承担了三种互不相容的职责：命名对照、决策理由、
开发过程记录。结果是三者的检索入口挤在一个文件里，读者要读完全文才能定位。

而且当时的判断缺少一个对照样本：`dsh-tavern` 用「薄 AGENTS.md + 根 CONTEXT.md + 有序 ADR +
按成熟度分层的 docs」支撑 200+ 文件不乱。2026-10-16 所有者要求工程纪律向它对齐，
本 ADR 即那次对齐的产物。

**代价（明确接受）**：

- 文档位置变了，跨仓库的旧链接会断。缓解措施：**D1–D26 原编号全部保留不变**，
  ADR 文件名即编号，因此 `src/` 与 `tests/` 注释里的 `D6`、`D21` 等引用零改动继续有效。
- `docs/reference/DECISIONS.md` 不再作为真源存在，改由本目录取代；已同步更新全部正式引用。
- 多了一次跳转（找到决策 → 打开 ADR）。换来的是单篇可独立阅读、可独立讨论、可独立标注状态。

**关系**：[ADR 0021](./0021-no-plugin-content-in-chat-flow.md) 定下「正文区属于宿主」，
本 ADR 定下「文档区如何组织」——同一条思路的两处应用：呈现面要有明确归属，不要混着放。

## 被否决方案

- **只建 `CONTEXT.md`，不拆 ADR**：47.8KB 的决策文件仍然是单点，且没有状态栏，
  被取代的决策只能靠正文里的「后续演变」段落区分，检索不到。
- **保留 `DECISIONS.md` 作为指针文件**：省掉改引用的功夫，但等于留一层永久间接，
  且新人不读指针就不知道决策已经拆分。
- **重编号 ADR（从 0001 重新编排）**：会让代码注释里既有的 `D14`、`D22` 引用全部失真，
  收益仅是编号更「干净」，不划算。

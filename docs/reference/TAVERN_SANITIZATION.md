# 酒馆卡清洗要点笔记（issue #19 · A2 参考）

> **性质**：思路笔记，非代码移植。源为本地只读参考克隆 `D:\projects\dsh-tavern-v2`（PolyForm-NC-Copyleft 协议）`lib/index.js` 的 `sanitizePromptText` 一族——**只吸收踩坑结论，实现自行重写，其代码不进入本仓库**。
> **用途**：D14 裁决「不兼容酒馆字段，未来靠 AI 转译」后，这张清单就是转译工具/转译 AI 的验收注意事项。

## 一、要清洗的两类病根

### 类 A · 模板变量（会直接报错）
ST 卡片/预设文本充满 `{{...}}` 宏，宿主不认识就会抛 malformed/unknown variable：

1. **无状态宏可在导入时一次性落地**：`{{random::a,b,c}}`/`{{pick::…}}` → 当场随机取一值；`{{roll::…}}` → 当场掷骰；`{{//注释块}}` → 删除。原则：**转译后不留活宏，全部固化为纯文本**（我们无宏引擎，也不该有）。
2. **有状态宏物理不可迁移**：`setvar/getvar` 依赖酒馆运行时变量存储——只能整体剔除，转译时检查其语义是否有对应的 WorldState 字段可转写（通常没有，忍痛删）。
3. **常见 ST 变量按语义映射或删除**：`{{user}}`/`{{char}}` → 对应我们的 `{{player.name}}`/卡角色名。**语义陷阱**（关联 #25）：酒馆的 `{{user}}` 是玩家全局自设，我们的是卡声明的既定角色——转译时若原卡文本依赖"玩家自填"语义，需转成中性第三人称，别留悬空指代。`persona/system prompt/description/scenario/mes_example` 等卡内字段宏 → 一般删空或换成卡包对应实体的转写。
4. **通用兜底是纪律不是可选项**：映射完已知宏后，必须有一条"清除一切剩余 `{{...}}`（含双冒号、中文名、点开头、跨行等怪形态），只放行白名单注册变量"的收口规则。白名单在我们的语境里 ≈ 我们自己声明的插值变量集。

### 类 B · 隐藏通道指令（不报错但毁输出）
为 Claude 等"有原生隐藏思考/注释通道"的模型写的指令，DeepSeek 系会**当正文原样输出**：

1. **成对隐藏标签整段删**：`<thinking_rules>`、`<output_lock>`、`<thinking>`、`<comment>`、HTML 注释 `<!-- -->`；残留的半个开闭标签也要单独再扫一遍（成对删除会漏掉被截断的半边）。
2. **草稿/规划类自然语言指令按短语删**：「打草稿：…」「At the START of every reply…」「内容输出规划」「思考链缝合」「每步思考字数限制」「贝叶斯推演与元素构建」等固定话术。教训：**这类指令是话术不是语法，正则清单会过时**——转译 AI 要按"意图"（要求模型先输出思考/草稿/规划再写正文）识别并剥离，而不是只背短语表。
3. **引用要改写而非留空**：文本内部互相引用的容器（如某流行套件的 `<Prism>`）删标签后，把「总结 <Prism> 内的所有要求」这类**引用句改写成自指完整句**（"总结所有写作要求"），否则模型读到悬空引用。
4. **容器标签与内容区分对待**：无害的容器标签（如 `<cot>` 在 deepseek 下不会触发隐藏输出）可只剥标签保留内容——判据是"宿主模型会不会把它当指令通道"，不是标签本身。
5. **清洗收尾折叠空行**：多轮删除会留下大片 `\n{3,}`，折叠以免污染排版与虚耗 token。

## 二、对我们转译器的验收清单

- [ ] 输出文本零残留 `{{...}}`（白名单除外）；
- [ ] 输出文本零成对隐藏标签与孤立半边标签、零 HTML 注释；
- [ ] 无"先输出思考/草稿/规划"类指令残留（按意图判定，非短语表）；
- [ ] 悬空引用已成自指句；
- [ ] `{{user}}` 语义已按 #25 的玩家角色模型落定；
- [ ] 连续空行已折叠；
- [ ] 全程一次固化，**运行时不做正则扫描**（我们的 C 决策：剧情理解归模型，注入层只放干净静态文本）。

## D1 · 插件组合成自定义 RP 模式

**决策**：以原生能力为主，先把基础 RP 做出来；DSH 支持插件组合成一个模式，我们组合出一个自定义 RP 模式即可。其他形态后续再考虑。

**理由**：宿主本身提供 profile / bundle 组合机制，我们不需要发明「应用」概念。

**含义**：
- 交付形态是一个可 `dsh plugin add` 的插件（未来可能聚合为 bundle）
- 不提供独立启动器、不抢占端口

---

## D2 · 先不做导演草稿板（Scratchpad）

**决策**：暂缓，或许目前根本不需要。

**理由**：保持最小可用；草稿板是复杂度来源，等真正感到需要再加。

**注意**：这不是「永远不做」，而是「不作为第一版范围」。若要加回，需重新评估对 TTFT 与 Token 的影响。

---

## D3 · Author 与状态记账异步（正文优先）

**决策**：采用异步方案 —— 正文毫秒级流式交付；正文落盘后，状态推演在后台执行。

**理由**：当前是开发阶段、个人玩具；优先保证打字机流畅体感。

**已知代价（接受）**：玩家手速极快时，可能在新状态刷新前就开始下一轮，此时 Author 消费的是稍旧的状态。**所有者明确接受这一时序**，不做强制锁步。

---

## D4 · Chronicler 是一个正经 Agent

**决策**：Chronicler 不是「JSON 提取器 / 正则处理器」，而是一个**有智能、有主观判断的 Agent**：它会思考「什么应该记录、什么应该更正」，并严格按规则执行变更，态度冷静稳定。

**含义**：
- 它有自己的系统提示词与判断准则
- 它可以决定忽略噪声事件、也可以决定强调重大变化
- 但必须在**规则约定范围内**行动（见 D5、D8）

---

## D5 · 世界状态结构动态演进

**决策**：状态结构**不锁死为固定四大模块**。在规则约定前提下，Chronicler 可以根据剧情与卡包，自行创建新的词条结构，甚至设定数值公式。

**背景（为什么要状态）**：酒馆本身没有真正的状态。所有者要这一层，是因为**角色会随剧情改变**；若人设从开局到结尾毫无变化，会导致严重剧情漂移与出戏。状态是「角色演进的载体」。

**边界**：
- 动态扩展必须**受规则约束**，不能随意发明与剧情无关的结构
- 保持可读：玩家必须能在侧边栏看懂
- 稳定性优先于花哨（配合 D8）

**实现状态（2026-09-19 同步，issue #23）**：**已兑现受控扩展部分；「数值公式」不属于当前承诺。**

已实现并测试（`tests/dynamic-fields.spec.ts` 覆盖三条写路径）：
- **模型形态**：扁平扩展——核心五域（characters/inventory/scene/flags/relations）之外的顶层键即动态字段，值为 `{ type: 'number'|'string'|'boolean', value, min?, max? }`（`src/world-state.ts` DynamicFieldValue；投影 zod `catchall` 强校验，`src/projection/world-state.ts`）。
- **命名与上限**：字段 ID `^[a-zA-Z0-9_]+$`、禁与核心保留字重复、总数 ≤ 32；number 支持 min/max，越界由 `applyConstraints` 钳制；`pruneWorldState` 在所有写路径统一裁剪。
- **创建通道**：Chronicler 输出契约的 `createFields` 数组（`src/agents/chronicler.ts`，非法 ID 逐条跳过）；创建后作为顶层键直接更新值，无需再次 createFields。
- **玩家编辑**：右侧栏动态字段编辑器（新增/改值/删除，ID 规则前端拒绝）。
- **渲染**：`renderWorldState` 将动态字段以「自定义状态字段」段并入 Author 事实基准；`diffWorldState` 对其变化生成摘要（含仅 min/max 调整）。

**字段名校验边界（务必知晓）**：ID 正则只在 **Chronicler createFields** 与**客户端编辑器**两处强制；**HTTP 矫正（`correction.ts`）与 Copilot patch** 只强制值形状（zod `{type,value}` + 保留键不可覆写 + 钳制/上限），**接受任意非核心顶层键名**（含中文）。即：直接打 HTTP 面可造出编辑器与推演契约不会产生的非常规 ID 字段——它们能正常渲染与折叠，但属约定外形态。如需收紧，在两条服务端入口补 `isValidFieldId` 即可（当时有意不做以保持简单；真机若因此出问题再加）。

**明确未做（后续再议）**：数值公式/派生字段（D5 原文的「设定数值公式」）；动态字段的枚举类型；字段级失效策略（目前移除=从切面删键）。条件注入（#16）对动态字段的 `when` 支持以 `type` 匹配的数值/布尔为限。

## D6 · 玩家矫正是自然时序，无锁（重要）

**决策**：**不存在「锁」，只存在「矫正」。**

**时序**：
```
Chronicler 更新状态 → 玩家查看 → 玩家觉得不对就改 → 玩家开启下一轮
                                                    ↑ 下一轮直接以改后的状态创作
```

**理由**：玩家的修改发生在 AI 修改**之后**、下一轮**之前**。这天然就是最后一次写入，下一轮自然消费它。因此：
- ❌ 不做 CAS 乐观锁
- ❌ 不做永久硬锁 / 保护盾
- ❌ 不做解绑（Unpin）通道
- ✅ 只做「覆盖 + 下一轮消费」

**实现边界（2026-09-20 更新）**：后端仍是无锁覆盖。UI 端在推演期间封口（`world-state-tab.tsx` 的 `isInferring` 拒绝编辑与保存）；后端另有一条**不是锁**的顺序裁决：若玩家矫正发生在推演飞行途中，本次 AI 结果作废（玩家优先），**但被作废那一轮的正文不会被丢账**——调度器记下待办边界，跑一次 covering rerun 从「已入账游标」重折到该边界，最多 3 次后交给下一次正常触发。游标本身随状态一起写进会话日志（`source.rrp.stateFoldSeq` → `TranscriptSlice.lastFoldSeq`），因此重启、续档、分叉后游标与状态始终一致；这也是「延迟轮次被后来的状态写入挤到日志前面」时唯一可靠的依据（`lastStateSeq` 会一并被 settings/lore/summary 发布推动，不能用）。

> **术语修正**：旧项目称「玩家最高仲裁权（Arbitration）」，现统一为 **玩家矫正（Player Correction）**。见 [`GLOSSARY.md`](GLOSSARY.md)。

## D7 · 知识体系全面 Skills 化

**决策**：世界典籍 / 酒馆世界书（Lorebook）这一层，**改用 Skills 概念实现**。

**理由**：
1. 最新一代模型在训练阶段就认识 Skills 这种形态；
2. Skills 天然契合「按需索引、渐进披露」，正好治酒馆「上下文硬塞」的病。

**权威参考**：[Claude Code Skills 文档](https://code.claude.com/docs/zh-CN/skills) · [Agent Skills 开放标准](https://agentskills.io)  
**DSH 实现**：`ctx.skills` 注册表 + `@deepseek-ai/dsh-skill-filesystem` 提供方。详见 [`SKILLS.md`](SKILLS.md)。

## D8 · 允许受控的动态知识沉淀

**决策**：希望支持「剧情中产生的新设定沉淀为知识」，但**必须保证效果**——不能过于激烈，导致世界观崩塌。

**含义**：
- 玩家发现的新秘密、新势力可以被沉淀
- 但沉淀必须**受控、可审阅、渐进**
- 不能由模型自由发挥式地重写世界观

**实现状态（2026-09-17）**：受控交互环已实现：默认关闭 / 仅明确触发（`/lore` 或面板）+ 二次确认 / 只新增不覆写 / 可审阅可删除 / 单次一条且四重上限。确认与删除写入已知 `user/message.source.rrp.sediment`，由 `rrpSediment` 纯投影折叠；agent-scoped provider 读取当前会话投影。原生 fork 因而继承分叉点前缀，分叉后的变化互相隔离。旧 session sidecar 只读迁移一次，成功写入快照后备份为 `.legacy.bak`。详见 [SKILLS.md](SKILLS.md) §4.3。

## D9 · 分支映射原生 Session.fork

**决策**：重新生成 / 分支一律使用 DSH 原生会话 fork（做法 A）。

**理由**：
- 旧项目的自定义分支结构是复杂度与幽灵状态的来源
- 原生 fork 天然保证历史不丢
- 状态由会话投影纯数学折叠，切分支自动得到正确切面

**实现范围（2026-09-17）**：上述保证覆盖 Card、WorldState、Summary、Settings 与 Sediment。前四者采用整值事件；Sediment 采用有界、可校验的 `snapshot/add/remove` 操作，但同样只依赖继承事件前缀做确定性重放。

## D10 · 与 dsh-synapse 协同，而非对标

**决策**：地图协同交给 `dsh-synapse`；它**只是参考，不是开发 DSH 插件的唯一标杆**。

**含义**：
- 我们不自建 DAG 画布平台
- 我们的责任是保证**在任何分支/任何会话切换下，属于世界线的领域状态不发生穿帮**；当前投影范围与回归证据见 [`HOST_BASELINE.md`](HOST_BASELINE.md) 与投影清单
- 学习插件开发规范应参考**广泛社区实践**与宿主勘察证据，见 [`HOST_SEAMS.md`](HOST_SEAMS.md)

**后续演变（2026-09-20， superseded 部分）**：#28 起我们自建了「世界线」页签（会话投影折叠 + 宿主 fork 血缘），#29 补齐冷启动骨架节点——**地图职责已由世界线页签接管，dsh-synapse 于当日从 rp-dev profile 撤装**（`dsh plugin --profile rp-dev remove dsh-synapse`）。协同关系终结，但两条历史结论仍有效：分支物理拓扑仍是 DSH 原生 `Session.fork`；synapse 作为插件开发规范的参考地位不变（本决策的"非对标"初衷正是不要被单一插件绑架）。

## D11 · 摘要由独立 Agent 负责

**决策**：摘要就是「按轮数提取、压缩、提供大局观」。**另起一个 Agent 负责摘要工作**，轮数可自定义；楼层数不高的卡，玩家甚至可以选择**关闭**该功能。

**含义**：
- 摘要不是 Chronicler 的附庸职责，是独立智体
- 默认按固定轮次（如 5~10 轮）后台触发
- 必须可一键关闭
- 开关属于当前 Session 的 `rrpSettings` 投影；新存档彼此独立，fork 继承分叉点设置

## D12 · 记忆能力外置（扩展层）

**决策**：记忆属于**我们插件之上的可扩展内容** —— 即接入外部记忆插件系统作为辅助，而不是内建在核心引擎里。

**方向**：`D:\projects\EverOS` 是很好的开源免费替代。

**理由**：保持核心轻量；记忆是独立演进方向，不该把向量库/索引引擎塞进 RP 插件。

## D15 · 个人玩具定位

**决策**：这是**个人玩具**，纯个人玩、个人使用；以后开源发布也是**一个玩家一个部署**。

**含义（明确不做）**：
- ❌ 生产环境高可用设计
- ❌ 压力测试 / 并发优化
- ❌ 多用户、鉴权、租户隔离
- ❌ 分布式一致性、集群部署

**含义（要做）**：代码简单、透明、可读，一个人能完整看懂并维护。

## D16 · 反八股句式清单：来源与协议评估

**决策**：将句式级中文 AI 腔禁令以硬约束形式常驻 Author persona（`presets/rp/agent.cordis.yml` 的「文风禁忌」段），具体清单为本项目自行归纳重写。

**理由**：硬约束必须常驻 always-loaded 的 persona，不能只放在 skill 里按需调取——与「防全知」从 skill 晋升铁律的教训同一逻辑（commit `837a191`）。

**来源与协议**：清单的事实性枚举参考了 dsh-tavern-v2（PolyForm-Noncommercial-Copyleft-1.0.0，本地只读参考克隆）。**未复制其代码**：只吸收「高频 AI 腔句式可以枚举成模板禁令」这一思路，措辞与选条均自行重写；该项目的代码资产不进入本仓库，避免非商业同协议传染。

**分工**：persona 常驻句式级禁令（每轮必查）；anti-cliche 技能保留人物/剧情套路与自查方法（技法层，按需调取），两者不重复维护同一份清单。

## D17 · 条件注入 v1：裁决式注入块 + 仅数值/布尔条件

**决策**：skill frontmatter 可选 `when: 条件`，框架对世界状态投影求值，命中即以「裁决式注入块」把片段（单条 800 / 总量 2000 字符，按 skill id 字典序截断）确定性写入 facts 通道。v1 字面量**仅允许 number/boolean**，字符串等值比较在解析期明确拒绝（报错附迁移提示：建模为布尔/数值字段）。

**理由**：
- **机制与内容分离**：框架写一次求值与渲染，卡作者只写声明数据，老卡零影响（`when` 可选）；
- **裁决式兜底**：渐进披露靠模型语义调取有方差，条件注入保下限——模型无权跳过；
- **字符串比较是命门**：Chronicler 自由文本写值 + 字符串等值 = 词表漂移静默失配（评审风险 2），v2 解锁必须配 Chronicler 词表写入契约 + zod 强校验；
- **缓存纪律**：注入块文本只由命中集合决定、不嵌实时数值（档内波动逐字节不变，复用 facts 指纹去重）；命中集缩小/清空时新块带撤销句 + 每块穷尽性声明「仅本块所列条目有效，此前所有条件注入一律作废」。

**已知并放弃**：
- **双通道重复**：模型语义调取命中 skill 全文 + 条件注入其片段 = 同一内容两份；注入块自带「无需再调」纪律，重复读取是浪费而非错误；
- **阈值抖动刷块**（79↔80 横跳）：v1 接受，真机出现再加迟滞；
- 多条件组合、互斥组、回合数数据源：v1 不做，语法向后兼容留作吸收点。

**实现**：`src/lore-condition.ts`（纯函数零依赖）；触发注册表为宿主内存 Map（按 cardId 索引，随卡包读取重建，重启即恢复）；触发状态不持久化，永远从状态确定性重算；注入块不进转录投影（Chronicler 反馈环物理隔离）。

**重启补正（2026-09-20）**：命中集本身确定可重算，但「上一块列了哪些条目」是历史事实，内存基线一丢就会静默留下无人撤销的旧块。故 `adopt()` 检测到已入账 facts 里含裁决块时标记基线未知，下一次发布强制带**全撤销句**（含命中集已空的情况，此时渲染「生效条目：（无）」）。

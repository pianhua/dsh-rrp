# 设定集与条件注入

> 两套互补的知识机制：模型按需调取的「上限」，和程序确定性注入的「下限」。

## 先分清两个东西

| | 技能 Skill（卡包自带） | 设定集 Lore（玩出来沉淀） |
| :--- | :--- | :--- |
| 谁写的 | 卡作者 | 你（游玩中确立） |
| 存哪 | 卡包 `skills/` 目录 | 本会话专属，随世界线走 |
| 怎么进上下文 | 模型按需调取（抬上限）；卡作者可写 `when:` 走确定性注入（保下限） | 只走模型按需调取（设定集条目没有 `when:`） |
| 生命周期 | 跟着卡 | 跟着这条世界线 |

这套设计**彻底淘汰了旧酒馆的正则世界书（Lorebook）**：没有关键词扫描、没有死板激活，知识就是 Markdown 文档 + 一句触发描述，模型像查资料一样自己决定什么时候看。

## 设定集：从剧情里长出来的知识

玩到中途，某条新设定被剧情真正确立了（比如「老宅井底封着一口剑」），值得长期记住？

1. 输入 `/lore 井底的剑`——知识起草智体（Scribe）基于已发生的正文写一条草稿；也可以直接让[月停](/guide/copilot)代劳起草；
2. 打开右侧栏 **设定集** 页签，看草稿；
3. **确认**才入库（或丢弃）。AI 永远只能起草，写进世界知识的笔在你手里。

页签里还能随时**删除**已入库的条目（只新增不覆写，所以没有「编辑」——要改就删掉重新沉淀一条）。每条显示触发描述；卡包的 `when:` 条件设定在页签顶部的独立分区，与会话条目分开显示。

## 条件注入：一行 `when:` 买断「保下限」

有些设定**绝不能指望模型主动查**——比如好感 ≥ 80 之后女主的亲密人设。漏注入一次，戏就断。这就是 `when:` 的战场：

```yaml
---
name: 米娅 · 亲密阶段
description: 好感≥80 的米娅人设
when: characters.米娅.affinity >= 80
---
（正文：这个阶段的她如何说话、动作、卸下防备……）
```

引擎的行为（全自动，你什么都不用做）：

- **每轮对世界状态求值**（纯数值判断，不是语义猜测）：命中 → 片段以「裁决块」形态确定性注入执笔的上下文，模型无权跳过；
- **块内自带穷尽声明**：「仅本块所列条目有效，此前所有条件注入一律作废」——条件回落时新块带撤销句，旧污染当场买断；
- **字节稳定**：块文本只由命中集合决定，不嵌实时数值，状态在阈值附近抖动不会打爆前缀缓存；
- **零持久化**：触发不写日志，永远从当前状态重算——读档/切线时注入自动严丝合缝。

::: warning v1 边界
`when:` 只支持**数值与布尔**比较（`> >= < <= == !=`）。字符串等值明确拒绝——自由文本的词表漂移会让保下限静默失效。想让某个「事实」可触发，把它记成 flag 布尔或数值字段。
:::

## 两者怎么配合

- 卡包技能的「生效中」状态在设定集页签顶部的**「卡包条件设定」只读区**可见（哪些 `when:` 此刻命中、本篇共注入多少字符）——这一区只反映**卡包 skills**；
- 沉淀出来的设定集条目**走的是另一条通道**（会话专属、随世界线 fork 演进、由 agent 作用域动态注册），因此**它没有 `when:` 字段**，不参与条件注入。要保下限的内容请写进卡包的 `skills/`；
- 月停看得到全部条目清单，问她「哪些设定现在是生效的」也是可以的。

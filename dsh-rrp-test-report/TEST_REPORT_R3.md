## 5. 缺陷记录清单 (Defect List)

### [DEF-04] P2: Author 英文 System Prompt 导致内部 CoT 构思与自纠英文旁白漏出至用户正文

- **发现用例**：T32（英文 persona 正文语言与文风审查）
- **严重程度**：**P2**（次要缺陷。不引起崩溃，不破坏会话持久化与推演，但严重破坏用户沉浸感并导致正文重复生成）
- **缺陷现象**：
  在主测 RP 会话第一轮交互（Turn 1，`seq: 8`）中，Author 在生成中文正文的后半段时，将自身构思与修改过程中的英文思考旁白直接输出到了 Markdown 正文区：
  > `……像个习惯了挡在别人前面的人（哈，don't over-explain）。Keep the last part without the parenthetical explanation. Just her posture. Then a voice through the door, muffled: 「快递——」 something. Actually should I include the voice? A muffled voice through the door is perceivable. Let's include: 门外传来一个男人的声音，隔着铁门听不真切，只隐约能辨出「……快递……有您的件」几个字。End there. Good.你还站在玄关没答话的工夫……`
  不仅包含了 4 句大段英文构思独白，而且由于模型内部自我纠偏（`Keep the last part... End there. Good.`），导致后半段正文内容被完整重复输出了两次。
- **复现步骤**：
  1. 使用 `rp-maid-heiress` 预设，模型选用 `deepseek-v4.1-flash`（通过 `acy` 渠道）；
  2. 针对开场白发送用户输入：`我愣了愣，赶紧把她让进屋里：「外面冷，快进来吧，先换双拖鞋。对了，刚才说什么和牛？」`；
  3. 观察 Author 流式输出，当生成到门外敲门人设与动作描写时，模型即发生英文内省独白并重复。
- **根因分析**：
  `c8f78e9` 将 Author 的 System Prompt 彻底重构为全英文。英文 Prompt 中包含了大量类似 `Do not over-explain`、`Keep sentences sensory`、`Show, don't tell` 等强指令。在模型以单阶段（Non-thinking 模式或直接流式输出）执行时，当遇到复杂的“展示 vs 解说”的边界抉择时，模型的内部反思（Self-reflection / Meta-reasoning）被英文 Prompt 激活并自然使用英文流出，且缺少硬性的“严禁输出任何思考说明、草稿痕迹、英文评论”的终止/过滤约束。
- **修复建议**：
  1. 在 Author 的英文 System Prompt 末尾追加强硬的语言纯净度与思考隔离铁律：
     > `OUTPUT FORMAT RULE: The final response MUST be 100% Simplified Chinese. NEVER output internal monologue, reasoning, planning, meta-commentary, or English instructions into the narrative response. Only output the final novel prose directly.`
  2. 评估是否在宿主或流式层针对类似 `Keep the last part...` / `End there. Good.` 等元提示词模式建立兜底防漏机制。
